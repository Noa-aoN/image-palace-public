# 進め方

1人で作っていますが、**あとから読める形**を優先しています。
判断の理由がコードとドキュメントに残っていないと、3か月後の自分が同じ検討をやり直します。

---

## issue

- ボードは「次にやる」を**5件前後**に保つ。増やすより育てる
- 思いついたものをその場で issue にしない。同じ話は既存の issue に書き足す
- 1,309 件（issue と PR の合計）のうち、ほとんどは
  「何が起きたか・なぜそう直すか」を書いた記録として残している

## ブランチと PR

- `main` は常にデプロイ可能に保つ。直接 push しない
- ブランチ名は `feature/<説明>` / `fix/<説明>`
- **PR の差分は 400 行以内**を目安にする。バグ修正は最小差分に保ち、
  頼まれていないリファクタを混ぜない
- タイトルとコミットは Conventional Commits（`fix: 日本語の要約`）。本文も日本語
- マージは既定 squash（main を線形・PR 単位に保つ）。
  履歴を粒度ごと残したい PR だけ rebase merge

PR 本文は4つ（[テンプレート](../.github/PULL_REQUEST_TEMPLATE.md)）。

1. **変更内容** — 何を変えたか
2. **変更理由** — なぜ。直した場合は「何が起きていたか」から書く
3. **テスト方法** — 実行したコマンドと結果
4. **残していること** — 直さなかったもの、分かっているのに今回やらないこと

4 を書く欄を自分で足しました。「全部直した」ように見える PR がいちばん危ないので。

## レビュー

1人なので、PR は**自分とは別の視点**に通してからマージします。
見る観点は、正しさ・読みやすさ・安全・テストの有無・パフォーマンスへの影響。

指摘は鵜呑みにせず、**根拠を確かめてから**反映します。
実際、直近の PR では指摘6件のうち5件が当たっていて直し、
1件（「ジョブも同じトランザクションで確定する」という自分のコメント）は
**自分の記述が誤っていた**ので、gem の実装を読んで確認してから書き直しました。

## テスト

- 新しいコードにはテストを書く。テストなしではマージしない
- **不具合は直す前に、落ちるテストで再現する。** 推測で直さない
- 外部 API（OpenAI 等）は必ずモックする
- テストは必ず**末尾が `_test` の DB** で走る。違う DB につながっていたら1件も走らせずに止める
  （気づかないうちに開発 DB で走っていたことがあるため）
- 順序依存を作らない（`config.order = :random`）
- 速さは測らず、**問い合わせの本数**を数える spec を置く（環境で揺れないので）
- 並行性は**実スレッド2本**で確かめる（トランザクションで包むと相手のデータが見えない）

```
RSpec   5,015 例 / 395 ファイル
RuboCop / Brakeman / bundler-audit
Vitest（フロントは、いまは純ロジックのみ）
```

## CI

無料枠を大きく超えたので（実測 4,900 分/月）、**PR ごとの自動実行は止めてあります**。
週1の実行と手動実行は残しています。

そのぶん、**手元で何を通したかを PR 本文に必ず書く**運用にしています。

```bash
docker compose exec -T web bundle exec rubocop
docker compose exec -T -e RAILS_ENV=test -e REQUIRE_VIPS=1 web bundle exec rspec
docker compose exec -T web bundle exec brakeman -q --no-pager
```

## 「完了」と書く前に

検証コマンドをその場で実行し、**出力と終了コードを確認してから**書きます。
実行していないことは「未検証」と明記します。

## ドキュメント

- 変わりやすい情報（API 一覧・依存の版・テーブル定義・設定値）は**コードを正本**にする。
  文書へ写すと必ず食い違う
- 文書に残すのは**人の判断**（なぜこれを選び、何を捨てたか）
- 意思決定ログ（[decisions/](decisions/)）は決めた時点で書く。あとから書くと結論しか残らない
- 判断が変わったら、**元の文書に追記して経緯を残す**（上書きしない）。
  「この記述は誤りだった」と書いた追記が実際に何件かあります
